# 乌东文旅平台四天开发 TODO 与人员分工

## 1. 四天目标

四天不追求完整实现需求文档全部功能，冻结为可演示 MVP：

```text
注册/登录 → 首页 → 衣/食/住/行浏览 → 商品加入购物车或直接预订
→ 创建订单 → Mock 支付 → 订单状态变化 → 个人中心查看订单
→ 商家后台查看订单 → 管理后台审核社区内容
```

一期明确不做：微信小程序、真实支付、短信真实发送、地图 SDK、自动备份、AI 推荐、路线跨模块库存联动、复杂财务结算、视频转码。

### 2.1 责任边界

- P1 是公共后端唯一维护者，其他人不得修改 `app/cool-admin-midway/src/modules/wudong/common`、Cool Admin 内置模块、订单公共表和认证代码。
- P2 是前台公共壳唯一维护者，业务人员只能在约定路由和页面目录内开发。
- P6 是集成负责人，负责解决冲突、合并 PR、发布演示环境；P6 不应等到最后一天才开始集成。
- P3/P4/P5 必须自己完成本模块最小后端接口和前端页面，不等待“全部公共功能完成”。

## 3. MVP 功能冻结

### 必须完成

- 普通账号注册、密码登录、退出登录
- 首页 Banner/模块入口/推荐数据（可使用种子数据）
- 衣：商品列表、详情、SKU 选择、加入购物车、商品订单
- 食：特产列表/详情；餐厅列表、简化餐位预订
- 住：民宿列表、房型详情、日期预订
- 行：门票或路线二选一完整闭环，电子票使用 Mock 二维码字符串
- 社区：游记发布、图片 URL、列表、详情、审核状态
- Mock 支付、订单列表、订单详情、取消订单、商家确认
- 管理员审核游记、商家查看自家订单
- 种子数据、演示账号、一键启动说明

### 必须降级

- 图片先支持 URL 或 MinIO 上传，不做视频
- 内容审核先做敏感词本地过滤，人工审核由后台状态切换完成
- 搜索先使用数据库 `LIKE`，只支持关键词和模块筛选
- 收藏、评论、消息、退款做最小可用接口；时间不足时展示静态/种子数据
- 库存先做数据库条件扣减；Midway Cron / `@cool-midway/task` 只实现订单超时释放任务骨架
- 复杂优惠、分账、发票、物流、动态定价不做

## 5. AI 协作规则

- AI 可以生成 CRUD、DTO、TypeORM Entity、Vue 页面、Jest 测试样例和 README 初稿。
- AI 生成代码必须由负责人员本地运行、阅读并提交测试；禁止直接复制未验证的支付、鉴权和库存代码。
- 给 AI 的任务必须带上下文：目录、接口契约、字段、错误码、验收条件和禁止修改的目录。
- 每次让 AI 改代码前先要求“只修改指定文件”；公共目录由 P1/P6 审核后合并。
- AI 生成数据库迁移后必须人工检查字段类型、索引、唯一约束和回滚影响。
- 不向外部 AI 提交真实密码、JWT_SECRET、手机号、身份证和商户密钥。

## 6. 每日同步机制

每天 09:00 站会，每人只回答：昨天完成什么、今天交付什么、当前阻塞是什么。每天 18:00 集成一次，P6 发布可运行版本。

提交格式：`feat(m1): 商品详情与加购`、`fix(common): 支付幂等`、`docs: 更新启动说明`。

阻塞超过 30 分钟必须在群里说明，不允许一个人独自等待或大面积重写公共代码。

## 8. 风险降级顺序

时间不足时按以下顺序砍功能，不砍主链路：

1. 删除评论、收藏、热搜和复杂统计
2. 行模块只保留门票或路线一个完整流程
3. 食模块保留特产购买，餐位预订改为展示页
4. 住模块保留静态房态 + 预订，不做动态定价
5. 上传改为已有图片 URL，保留审核状态演示
